# 许愿树的自然落花

旧表现有三个问题：随机初始相位让花叶第一次就出现在半空，47–88 秒的周期使下降几乎看不出来，树交互粒子从树干附近向上喷射。底部装饰又是独立闪烁的图块，与落花没有连续关系。

现有模型全部替换为连续生命周期：

1. **树冠出生**：六个与插画树冠重合的发射簇，首次进入不会在空中或地面预填花叶。常态每 0.37–0.83 秒自然落下一片。
2. **下降与风**：8–13 秒从真实出生位置降到树下草地，纵坐标连续单调增加；侧风偏移、摆荡、旋转和翻面只作用于同一片花瓣，不跳换位置。
3. **落地**：位置固定，图形压扁贴地，停留 2–4 秒；随后用 2.4–4.2 秒缓慢淡去。没有独立闪烁的地面花瓣，也不再从脚下生成新的粉色方块。
4. **层次**：约三分之一的落花属于后层，在树冠和树干轮廓内被遮挡，位于人物后方；其余少量前层位于人物前方。落地花瓣始终在地面层。
5. **互动**：触碰许愿树或按 F 后，18 片花瓣在约两秒内陆续从树冠落下，风带来稍大的横移。没有向上爆炸式喷射。

四种樱花瓣为代码原生像素形状：不对称圆肩、凹口、收尖、细小折线与柔和粉红渐层，替代原有矩形拼块。

对话框保留环境自然运行；重复拍照使用相同时间，不额外推进花瓣。减少动态时冻结并隐藏运动花瓣，切换区域清空旧花瓣。新区域若没有叶片配置也可安全渲染。

`tests/petals-v5.py` 校验实际模型的完整轨迹、落地驻留、渐隐、冠内起点、互动释放、拍照重复绘制、减少动态与切图；报告 `output/petals-v5-report.json`，截图 `output/petals-v5-birth.png`、`output/petals-v5-8.png`、`output/petals-v5-16.png`、`output/petals-v5-gust.png`。

原有水流、海浪、瀑布和池塘处理保留。区域可通过 `sceneryWater`、`sceneryLights`、`sceneryRipples` 和 `fireflyPoints` 配置湖水、灯光、涟漪和萤火位置。

月见湖谷使用实际插画对应的 17 点湖水轮廓，右下木码头完全排除；首次缓存时再用原图颜色辨识水面，荷叶、荷花等保留原画。水面有低幅位移、三处舒缓扩散涟漪与细碎反光，岸边七组萤火与灯笼缓慢明灭。`tests/lake-scenery-v5.py` 比较两秒间隔：湖水 24,315 像素发生变化，码头、荷花、荷叶核心和陆地检测区均为 0；连续绘制未增加像素回读，浏览器无错误。截图 `output/lake-living-v5.png`、报告 `output/lake-scenery-v5-report.json`。
