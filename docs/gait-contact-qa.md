# 步态连接与接地验证

旧 `side-walk.py` 检查侧面八帧是否不同、脚部像素是否足够、步幅是否变化，并要求头部像素完全不动。`character-v4.py` 检查所有姿势非空、透明边缘、颜色数量和帧数。这些检查可以发现缺图、动作完全静止和粗糙边缘，却没有测腿和身体的连接、脚底相对地面的位置；图像有八个不同哈希也可能是八张悬空的图。

现有 `tests/gait-contact.py` 覆盖女生/男生 × 四个朝向 × 八步加待机，共 72 个缓存帧；再通过真正的 `IslandCharacter.draw` 绘制 432 个结果，包含默认游戏人物比例、DPR 1/2、缩放 0.7/1/1.6。所有测试都是正常站立/行走，未把按空格跳跃、坐姿或特殊活动纳入强制接地判断。

检测内容：

- 透明度达到 128 的像素建立八连通图，找到躯干主体，再检查脚部区域是否有较大的独立残片。提灯和手持物不属于脚部区域。
- 逐行查找腿部横向透明缝，不把双腿之间正常的纵向间隙当成断裂。
- 用 `maxPixelY + 1` 作为靴底边界，与角色地面锚点比较；允许正负一个实际设备像素的栅格化误差，不使用阴影代替脚底。
- 记录靴底连续接触宽度，每个正常行走相位至少有一只靴接地；两只脚都抬离地面会失败。真实阴影同时绘制，并验证脚底与阴影在垂直方向交叠。
- 检测器自身有三个合成对照：连通腿加独立提灯应通过，切断两条小腿应报错，将整个角色抬高六像素应报双脚离地。

前版证据固定在 `output/gait-contact-before-source.js`，可用 `python tests/gait-contact.py --baseline --label before` 重现。该版本并没有大块腿脚完全透明脱离，不能把用户看到的所有不自然表现都归为透明断层；侧面逐行腿部变形、正面从 y=146 镜像下半身会带来纹理和关节位置不一致，仍需要放大图审查。

前版缓存中男生正面待机脚底比 anchorY=184 高 2 个源像素，其余大多高 1 像素；实际绘制的原点取整与待机整图呼吸叠加，使差距随 DPR/缩放扩大，DPR 2、缩放 1.6 下女生达到 3 个设备像素，男生待机达到 5 个设备像素。报告保留全部逐帧数据，不用总帧数或哈希代替接地质量。

输出包含 `gait-contact-<label>-report.json`、男女四向九帧腿部放大标尺图、真实缩放图，以及原始 atlas index 0/1/3 的裁切参考图。橙色线为 ground anchor；红色框标记与躯干分离的脚部组件。

旧侧面测试保留像素清晰、交替动作和步幅检查，将“头部完全不动”改为头部质心移动与面积变化在合理范围内。它和接地测试分别负责动作存在、画面稳定与结构正确，不相互替代。连通和接地检查仍不能自动判断一个关节弯曲是否美观；最终需同时看带标尺的图以及世界中的连续步行。
